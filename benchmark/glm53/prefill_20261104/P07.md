# P07：合并版 DeepGEMM MegaMoE 不直接纳入本组 GLM 对比

结论：固定 GLM5.3 Channel FP8 的 per-token 激活量化语义时，DeepGEMM develop pin `a1efb4e619e232a40f3b13eb8f2c5b12a8867740` 的当前 fused MegaMoE 不能原样替换。问题不只是跨宿主 IPC；实际 L1→L2 epilogue 使用 groupwise scale，不能靠单测容忍误差把不同量化流程当作等价。

## 原生源码证据

| 文件 / 行 | 实际行为 |
| --- | --- |
| `csrc/megamoe/kernels/params.h:215` | 为使每个L1 tile独立量化SwiGLU结果，定义 `kGroupQuantSize=128` |
| `csrc/megamoe/kernels/buffer_layout.cuh:148` | 每token分配 `intermediate_hidden / kGroupQuantSize` 个L2 scale；GLM I=2048对应16个预留scale，而基线激活为每token一个scale |
| `csrc/megamoe/kernels/gemm_device.cuh:605` | 按 `(token * sf_stride + n_blk)` 写scale，跨N tile并非一个全行amax |
| `csrc/megamoe/kernels/mega_moe_kernel_unified.cuh:272` | HT路径group大小取 `kL1BlockN/2`，L2以相同分组消费；具体tile可对应128/256列组，不能称为全2048维per-token量化 |
| `csrc/megamoe/kernels/gemm_device_ht.cuh:1237` | 每组归约amax并量化，另有FP8 amax下限1e-4；`fast_math=False`不把groupwise改成per-token |
| `op_test/test_mega_moe_fp8.py:1634` | 测试自身明确说明 fused intermediate是per-128-group、reference是per-token，并用既定误差容忍比较 |

头部说明、Python注释及暴露的1D scale view仍有per-token字样，不能覆盖上述真实分配、写入与L2消费路径。逐文件SHA256和原生代码节选保存于 `P07_results.json`。基线GLM的routed SwiGLU/quant以完整intermediate行产生一个scale；原安装包与容器源码已冻结，不能通过改模型量化策略来追求单项收益。

## 已做的原生验证

编译仅选官方setup.py的 `deepgemm.mega._C`，保留原 `deepgemm.op`；build.rc=0，扩展SHA256 `8e900c9894fea6b080ec3c3946d41a7fdfbede8151a39e9ef36f400096dcff18`。未运行完整fused MoE或模型性能，因此没有MegaMoE加速成绩。

p2c1/p2c9各1 rank，2MiB uncached allocation、64-byte HIP IPC句柄互换后，两端 `hipIpcOpenMemHandle` 均报 `invalid device pointer`。命令/日志保留；进程退出后两台卡均释放，再启动其他实验。这个结果只限制当前pin原样HIP IPC路径，不能认定HyLink fabric硬件不支持。

DeepEP normal MNVL使用256-byte HSA RPC fabric handle、finegrained分配及PCI agent映射，和HIP IPC不同。已准备公共HIP/HSA读写probe，但在确认量化语义不匹配后没有占卡执行：即便基本fabric读写通过，也不能证明MegaMoE的system atomics、fused正确性或GLM量化兼容。

## 代码与后续边界

实验adapter曾提交在 `86a0f2dcec`，历史保留供检查；当前交付移除本次新增的 `deepgemm_mega` runtime分支和adapter，保留仓库原有 `deep_gemm` / `megamoe` 后端。其他候选继续独立验证，P07不混入组合，也不把不同量化的结果算为GLM优化收益。

若以后继续移植，需要算子库提供保持GLM per-token量化、舍入/clamp/零行规则的明确兼容ABI，完成跨宿主buffer与原子一致性验证，并检查权重重排后的原始/packed副本生命周期和显存。之后才能复用原单测及同包、同拓扑的模型A/B。这些库改造尚未实现，不在本次固定语义对比中声称完成；本次对当前pin的适用性结论是排除，而不是宣称MegaMoE算法或HyLink永远不可用。
